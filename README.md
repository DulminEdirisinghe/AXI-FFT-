# AXI-FFT-
A basic implementation of AXI-FFT IP to plot the Fourier Transform of the DDS compilers output. Implemented on an Arty -a7 100t  board. 

## Requirements

- **Vivado and Vitis 2025.1.** The project script and the block design were generated with 2025.1. Other versions will likely ask you to upgrade the IP.
- **Arty A7-100 board files.** In Vivado: *Tools → Vivado Store → Boards*, search for **Arty A7-100**, and install it.
- **Python 3** with `pip install pyserial numpy matplotlib`, for the plotting script.

## Repository layout

| Path | Contents |
|---|---|
| `rebuild_project.tcl` | Recreates the Vivado project (block design, constraints, run settings) |
| `src/xdc/base.xdc` | Constraints |
| `work_proj/dma/` | Original Vivado project (`dma.xpr`, block design `.bd`, IP `.xci`) and the exported `dma_bd_wrapper.xsa` |
| `sw/dma_app/src/` | MicroBlaze application source and linker script |
| `sw/dma_platform/hw/dma_bd_wrapper.xsa` | Hardware handoff for Vitis (includes the bitstream) |
| `sw/plot_fft.py` | Receives FFT frames over UART and plots them |

Build outputs (synthesis/implementation runs, IP output products, the Vitis BSP, build folders) are not in the repo. They are regenerated by the steps below.

## Rebuilding the hardware (Vivado)

1. **Clone to a short path**, for example `C:\fpga\AXI-FFT`. The MIG (DDR3) IP creates very deep folders, and Vivado fails with *"Path length exceeds 248-Byte maximum allowed by Windows"* if the clone is nested deep (for example under `Documents\...\...`).
   ```bash
   git clone https://github.com/DulminEdirisinghe/AXI-FFT-.git C:/fpga/AXI-FFT
   ```
2. **Recreate the project.** From a Vivado 2025.1 command prompt:
   ```bash
   cd C:/fpga/AXI-FFT
   vivado -mode batch -source rebuild_project.tcl
   ```
   Or, in the Vivado GUI: *Tools → Run Tcl Script…* and select `rebuild_project.tcl`.

   This creates the project in `rebuild/dma.xpr`, which is ignored by git. It takes a few minutes. Expect one critical warning about `/xfft_0/s_axis_config_tvalid` being tied to 0. That pin is unconnected in the design, so the FFT runs with its default configuration.
3. **Build the bitstream.** Open `rebuild/dma.xpr` and click *Generate Bitstream*. Synthesis, implementation and the bitstream all run from that one step.
4. **Export the hardware.** *File → Export → Export Hardware*, choose **Include bitstream**, and save as `dma_bd_wrapper.xsa`.

> If you only want to run the design, you can skip steps 1–4. Use the `.xsa` that is already in `sw/dma_platform/hw/`; it contains a built bitstream.

## Building the software (Vitis 2025.1)

The Vitis workspace files store absolute paths from the original machine, so create fresh components and add the sources:

1. Open Vitis and pick an empty folder as the workspace. Keep this path short too.
2. **Platform:** *File → New Component → Platform*. Name it `dma_platform`, select the `.xsa` (your exported one, or `sw/dma_platform/hw/dma_bd_wrapper.xsa`), OS **standalone**, processor **microblaze_0**. Then build the platform.
3. **Application:** *File → New Component → Application*. Name it `dma_app`, select the `dma_platform` platform and the `standalone_microblaze_0` domain, and use the *Empty Application* template.
4. Copy the `.c`, `.h` and `lscript.ld` files from `sw/dma_app/src/` into the new application's `src/` folder, replacing the generated `lscript.ld`. Then build the application.

## Running

1. Connect the Arty A7-100T over USB.
2. In Vitis, *Run* (or *Debug*) `dma_app`. This programs the FPGA with the bitstream from the platform and downloads the ELF to the MicroBlaze.
3. Check which serial port the board's UART uses (Device Manager → *Ports*), then start the plotter:
   ```bash
   python sw/plot_fft.py --port COM5
   ```
   Run `python sw/plot_fft.py --help` for more options (`--baud`, `--shift`, `--fs`, `--record`).

## Updating the project script

If you change the block design, regenerate the script from the Vivado Tcl console with the project open:
```tcl
write_project_tcl -force -paths_relative_to <repo root> rebuild_project.tcl
```
Afterwards, re-apply the fixes this repo's version contains:
- remove the import of `utils_1/.../dma_bd_wrapper.dcp` and the `incremental_checkpoint` property, because that file is over 100 MB and not committed;
- replace the hard-coded `board_part_repo_paths` with the Vivado Store lookup block;
- set `origin_dir` to the script's own folder so the script works from any directory.
